# F103控制板模式与通信

适用：F103 `2.1.0-normal` / `2.1.0-debug`，配套H750 `2.4.1-green-ekf`，位于main分支。正常模式上电自动进入，不依赖电脑或H750发送开启命令。模式由编译配置决定，串口不能切换。

## 两种模式

| 项目 | 正常固件（默认） | 调试固件 |
| --- | --- | --- |
| 编译配置 | `DART_F103_DEBUG_MODE=OFF`（宏值0） | `DART_F103_DEBUG_MODE=ON`（宏值1） |
| STATUS | `mode=NORMAL mode_id=0` | `mode=DEBUG mode_id=1` |
| PWM | 初始化后自动持续输出四路50 Hz；每路初值1500 μs | 初始关闭；按命令手动开启、关闭、设置1000～2000 μs |
| PWM超时 | 无需KEEP，不因3秒超时关闭 | 开启/设置/KEEP后3秒无PWM续期关闭输出 |
| IMU | BMI088与72 MHz时钟检查通过后自动1 kHz采样，持续发送H750 | 初始关闭；可由电脑或H750请求START/WATCH/STOP |
| IMU超时 | 不受12秒会话限制 | START 12秒后停止；WATCH无限采样直到STOP |
| H750结束录像 | F103采样、发送、PWM继续；H750关闭自己的接收窗口 | IMU STOP停止采样；不影响PWM |
| PWM与IMU关系 | 并行 | 可独立启停、并行工作 |

当前正常模式持续输出的是四路1500 μs保持信号，没有新增姿态闭环或从识别结果计算舵量的控制律。BMI088配置仍为陀螺仪1000 Hz、加速度计1600 Hz，TIM3按1000 Hz读取并发送；这不保证每包加速度数据都是新值，以FRESH位为准。

PWM由TIM2硬件持续产生，PA0～PA3分别为CH1～CH4，计数单位1 μs、周期20000 μs。IMU由TIM3中断采样。两者不再互斥；重复IMU WATCH不会重启计时器或清零样本序号。`sequence`及`missed_ticks`从上电累计，H750按自己的接收窗口划分记录。

正常模式不因电脑断连、H750停止记录或红灯而关闭PWM/采样。IMU芯片或时钟检查失败时`active=0`，START/WATCH返回错误；PWM依然输出初始保持值。LED显示和控制模式独立。

## 标志位及其设置方

这里区分本地状态和串口中真实发送的位。模式配置不是需要持续下发的控制包。

| 标志/字段 | 所属方 | 设置方或来源 | 含义 |
| --- | --- | --- | --- |
| `DART_F103_DEBUG_MODE` | F103编译配置 | 构建时设置，默认0；无串口发送方 | 0正常、1调试；重新烧录对应固件后生效 |
| `control.mode` | F103本地 | 上电从编译配置初始化 | NORMAL=0 / DEBUG=1；运行期间不切换 |
| `control.pwm_requested` | F103本地 | 正常模式上电置1；调试模式由电脑PWM命令设置 | 请求PWM输出 |
| `pwm_on`（STATUS中的`pwm`） | F103本地 | TIM2配置完成后由F103更新 | 实际PWM定时器启用标志 |
| `control.imu_requested` | F103本地 | 正常模式上电置1；调试模式由电脑/H750 IMU命令设置 | 请求IMU采样 |
| `sampling`（STATUS中的`active`） | F103本地 | F103检查BMI088/时钟后启动TIM3 | 实际采样启用标志 |
| `control.watching`（`watch`） | F103本地 | 正常模式固定1；调试WATCH置1、START/STOP置0 | 是否绕过调试用12秒采样超时 |
| `imu_session.accepting` | H750本地 | H750准备好记录窗口时置1、停止时先置0 | 是否接收IMU包进入记录队列；不控制F103的正常模式 |
| `imu_session.started` | H750本地 | 收到F103的STARTED/WATCHING应答 | 采样确认，用于准备就绪判断 |
| `imu_session.released` | H750本地 | 收到F103的STOPPED/CONTINUOUS应答 | 已确认结束记录请求；不等于F103一定停止采样 |
| `led_state` | F103本地 | H750周期发送`LED n` | 记录器指示灯状态，与PWM/IMU启停分离 |
| `dart_imu.flags` | F103→H750的32字节IMU载荷 | F103逐样本生成 | 有效、新鲜、SPI错误、调度延迟位，见下表 |

`dart_imu.flags`沿用原协议，不增加模式位、不改变32字节载荷：

| 位/掩码 | 名称 | 含义 |
| --- | --- | --- |
| bit0 / `0x01` | `IMU_GYRO_VALID` | 陀螺仪配置有效 |
| bit1 / `0x02` | `IMU_ACCEL_VALID` | 加速度计配置有效 |
| bit2 / `0x04` | `IMU_ACCEL_FRESH` | 本次读取时加速度计报告新数据 |
| bit3 / `0x08` | `IMU_GYRO_FRESH` | 本次读取时陀螺仪报告新数据 |
| bit4 / `0x10` | `IMU_SPI_ERROR` | 本次SPI读取出错，同时清除VALID/FRESH位 |
| bit5 / `0x20` | `IMU_SCHEDULE_LATE` | 本次采样耗时超过800 μs |

## 发送方与命令

电脑↔F103为USART3（PB10/PB11，115200），ASCII文本以换行结束。F103↔H750为F103 USART1（PA9/PA10）连接H750 USART3（PB10/PB11），921600，使用现有COBS+CRC协议。

| 命令/数据 | 发送方→接收方 | 正常模式 | 调试模式 |
| --- | --- | --- | --- |
| 正常模式开启 | 无发送方；F103上电本地执行 | 自动启动PWM和IMU | 不适用 |
| `MODE ...` | 电脑/H750→F103 | 拒绝：模式固定在固件中 | 同左 |
| `STATUS` | 电脑→F103 | 返回模式、实际启用状态、IMU错误、四路脉宽 | 同左 |
| `PWM ON/OFF/KEEP`、`PWM <ch> <us>` | 电脑→F103 | 拒绝，正常输出不受手动调试命令影响 | 手动控制；H750发送PWM命令仍被拒绝 |
| `IMU START` | H750→F103，或电脑本地调试 | 确认持续流，回复`IMU STARTED`，不重置序号 | 启动采样并设置12秒期限 |
| `IMU WATCH` | H750→F103，或电脑本地调试 | 确认持续流，回复`IMU WATCHING`，不重置序号 | 启动无限采样 |
| `IMU STOP` | H750→F103，或电脑本地调试 | 继续采样，回复`IMU CONTINUOUS`；若IMU未就绪则回复`IMU STOPPED` | 停止采样，回复`IMU STOPPED` |
| `DART_IMU`（类型1） | F103→H750 | 持续1 kHz目标发送 | 仅采样启用时发送 |
| `DART_SYNC`（类型4） | H750→F103→H750 | H750发4字节时间戳；F103回复原值+自身微秒时间戳 | 同左 |
| `LED n`（类型2） | H750→F103 | 1准备、2就绪、3记录、4保存、5完成、6故障、7USB；3.5秒未更新显示故障 | 同左 |
| `F103 ALIVE`（类型3） | F103→H750 | 主循环约每秒心跳，不控制PWM/采样 | 同左 |
| `H7 <命令>` | 电脑→F103→H750 | 转发H750状态/记录命令，不改变F103模式 | 同左 |

正常工作不需要电脑发送以上任何开启命令。H750保留WATCH/STOP以确认就绪和管理记录窗口；F103不会据此关闭正常模式的持续服务。`H7 STOP`或`H7 AUTO OFF`停止的是H750的记录，并不是舵机关闭命令。

## H750配套变化

H750从准备完成到记录结束打开本地IMU接收窗口。关闭窗口后，仍会收到F103数据，但在USART中断中直接丢弃这些IMU包，不进入记录队列或命令回复队列。原实现会把窗口外IMU包放入回复队列，不适合常时发送。

停止时先关闭接收窗口，再发送IMU STOP；F103正常模式回复CONTINUOUS，调试模式/旧版F103回复STOPPED，H750都能处理。已在队列中的最后一批样本仍按原逻辑处理。记录、EKF、TF写入方式沿用main，不含开发分支的异步写回优化。

## 构建、标定与验证

CMake默认`DART_F103_DEBUG_MODE=OFF`。普通构建输出正常固件；调试固件用独立目录配置`-DDART_F103_DEBUG_MODE=ON`，再构建`dart_f103`。这个选项与CMake的Debug/RelWithDebInfo优化级别是两件事，使用`dart-debug`预设本身不会改成手动调试模式。

本次普通构建在`build/f103-dual-mode`，F103版本`2.1.0-normal`，配套H750版本`2.4.1-green-ekf`；独立调试构建在`build/f103-debug-mode`，F103版本`2.1.0-debug`。`manifest.json`及上电STATUS用于辨别模式。F103烧录工具新增`--build-dir`，避免误用别的构建目录；未自动烧录。

手动舵机标定使用调试固件。`tools/servo_calibrate.ps1`先检查版本和模式，普通固件拒绝进入标定操作；CheckOnly仍只查询状态。调试固件先请求H750停止自动记录，再停止本地IMU/PWM、设置四路脉宽、开启并续期，退出关闭PWM。脚本不会自动切换模式。

`python tests/run_tests.py`对正常/调试两种编译配置分别测试：开机请求状态、正常模式跨3秒/12秒及计时回绕不停止、录像停止仍连续发送、调试超时及续期、脉宽边界、并行PWM/IMU、真实协议编解码及H750窗口外60000个IMU包不被接收。另验证两块固件编译及存储区域布局。主机测试不代替示波器PWM波形、BMI088采样和两板串口吞吐实测。
