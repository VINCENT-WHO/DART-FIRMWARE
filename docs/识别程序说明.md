# H750 RGB绿色区域识别与固定曝光

当前版本：`2.2.1-rgb-roi3ms`。直接识别绿色像素，并在检出后使用上帧外接矩形的1.5倍范围搜索。固定曝光和RGB阈值沿用2.2.0。

## 固定曝光

目标3 ms，关闭自动曝光，保留自动增益。固定曝光不等于固定亮度：增益、相机ISP和现场光照仍会影响输出。

正式录像强制XCLK=24 MHz，PLL寄存器为3034=0x1A、3035=0x11、3036=0x78、3037=0x13、3108=0x01；对应系统时钟96 MHz，HTS=1892。

```
行周期 = 1892 / 96000000 = 19.708333 µs
曝光行数 = round(3000 / 19.708333) = 152
配置曝光时间 = 152 × 19.708333 = 2995.667 µs，约2.996 ms
曝光寄存器 = 152 << 4 = 0x00980
3500=0x00，3501=0x09，3502=0x80
3503 bit0=1（手动曝光），bit1=0（自动增益），其他位保留
```

采用整数行曝光，目标3 ms的量化误差约-4.33 µs。换算和寄存器位定义参照 [Linux OV5640驱动](https://github.com/torvalds/linux/blob/master/drivers/media/i2c/ov5640.c) 的 `ov5640_get_sysclk`、`ov5640_set_exposure` 和 `ov5640_set_autoexposure`。

初始化稳定600 ms后回读PLL、HTS、曝光寄存器和手动模式，任何不匹配均让相机配置失败。`INFO.TXT` 和 `IMU.DLG` 会记录曝光设置、回读结果及算法阈值。这里的时长根据配置计算，不是示波器测量值。

配置见 `h750/camera_exposure.h`，调用见 `h750/camera.c`。测试命令中的 `CAM CLK12` 不再改变正式录像的24 MHz时钟。

## 识别步骤与初始参数

1. 输入相机320×240 YUV422（Y0 Cb Y1 Cr），在本帧搜索范围及滤波所需1像素邻域内按BT.601全幅定点换算为RGB。每两个像素共享色度计算。
2. 对G通道二值化，并排除接近白灰、没有绿色优势的像素：

   ```
   G >= 140
   G - (R+B)/2 >= 20
   ```

   代码用 `2*G-R-B >= 40`，无HSV、浮点或除法。第二条按像素执行，R和B的均值指同一像素的两个通道均值，不是整块区域的均值。
3. 单张绿色掩膜做3×3滑动中值，边界复制，窗口至少5个有效像素才输出255。
4. 提取8连通域，统计绿色像素数、包围盒、坐标和。大区域完整消费；工作栈满时用位图保存未展开像素，避免把大背景切碎成假目标。
5. 在搜索范围内保留面积40～6144的区域，取绿色像素数最多者。同面积时保留按行扫描最先遇到者。
6. 输出绿色像素质心和外接矩形，在录像中画黄色矩形、红色中心及坐标；更新下一帧搜索范围。

### 跨帧搜索范围（ROI）

- 新会话或没有历史目标时搜索全图。
- 检出外接矩形 `(x,y,w,h)` 后，以**外接矩形中心**为中心，将宽高各放大1.5倍。左右各扩 `w/4`，上下各扩 `h/4`；离散像素边界向外取整，即各扩 `ceil(w/4)`、`ceil(h/4)`。
- 扩大后裁到 `[0,320) × [0,240)`，不平移另一侧来补足被裁掉的宽高。整数取整可能使实际宽高略大于1.5倍，例如10×10得到16×16，20×20得到30×30。
- RGB二值化、中值滤波、连通域和面积筛选均限制在搜索区域。RGB额外读取1像素邻域，中值只在实际图像边缘复制，保证搜索区域内结果与全图滤波相同。YUYV按像素对取色度，支持搜索框从奇数列开始。
- 局部没有合格目标，或选中目标贴到搜索框的**非图像边界**时，当帧回退全图，避免截断目标导致框逐帧缩小。回退失败则下一帧也搜索全图。回退成功则用新目标重新建立ROI。
- 局部搜索成功时，框外更大的绿色区域不会抢占当前目标。没有运动预测、跨帧坐标平滑或多目标ID关联。
- 每次开始录像调用 `det_reset_tracking()`，不继承上次会话ROI；算法接口用于另一路视频时也需要调用它。原始帧保持只读。

一次回退可能执行局部和全图两轮处理，耗时会按步骤累加到同一帧；总评估帧数只加1。实际加速幅度等板端实测，不使用旧曝光录像验收。

面积现在是**中值后绿色连通域的像素数**，不再是旧算法的白芯轮廓多边形面积。白孔和非绿色像素不计入面积。保留原最小面积数值40，但含义已变。

| 参数 | 初始值 | 含义 |
| --- | ---: | --- |
| `DART_DET_G_MIN` | 140 | G通道最小值 |
| `DART_DET_GREEN_EXCESS_MIN` | 20 | G相对R/B均值的最小优势 |
| `DART_DET_MEDIAN_KERNEL` | 3 | 中值窗口 |
| `DART_DET_AREA_MIN` | 40 | 最少绿色像素 |
| `DART_DET_AREA_MAX` | 6144 | 最多绿色像素，画面8% |

这些是待新曝光实拍验证的初始参数。本版本不再执行长宽比、圆度和绿色邻域筛选，主目标在本帧搜索区域内由面积决定。满足通道差条件的黄/青物体、绿色反光也可能入选，需在实拍中检查；不把“有输出”视为“正确识别”。

## 图像与日志

识别只读原始帧，中值及连通域只修改独立掩膜。之后才在原始帧上画文字、黄色外接矩形、红十字和中心点；最后按4:2:0、质量75做硬件JPEG压缩并写AVI。下一帧搜索框不额外画入录像。

| 文件 | 内容 |
| --- | --- |
| `VIDEO.AVI` | 检测后标注的320×240 MJPEG录像 |
| `DETECT.CSV` | 原有6列：帧号、相对时刻us、检出、质心X/Y、半径 |
| `TIMING.CSV` | 原有13列总流程计时、RGB识别7列、初始搜索框和模式5列，总25列 |
| `INFO.TXT` | 汇总、7步骤平均/最大耗时、曝光配置和回读结果、RGB阈值 |
| `IMU.DLG` | 原始数据和事件，包含版本、EXP与RGB配置事件 |

新分步耗时列依次为：识别初始化、RGB绿色二值化、绿色中值、扫描及收尾、绿色连通域、面积筛选、最大目标选择，单位µs。失败/拒绝路径已执行的阶段也累计，未执行阶段为0。墙钟计时含中断，阶段边界有少量开销。

末尾新增 `初始搜索X_px,初始搜索Y_px,初始搜索宽_px,初始搜索高_px,搜索模式_0全图1局部2回退`。搜索框记录本帧第一次尝试的范围；模式2表示局部后全图回退，耗时包含两轮。

仍先在RAM记录最多600帧，停止后导出。超过容量的帧仍参与汇总，并报告丢弃明细数。解析CSV应按列名；旧双层掩膜的10列内部阶段不再适用。

`dart_detection` 的旧圆度和绿色支持比例字段仅为结构兼容保留，固定为0；`area_q8`为绿色像素数×256，`score_x10000`为绿色像素数×10000。`radius`与DETECT.CSV原半径列仍保留兼容，实际标注改用外接矩形。

## 构建与验证

```powershell
cmake --preset dart
cmake --build --preset dart-h750
python tests/run_tests.py
```

H750使用CMake；`tools/build.py`是早期构建脚本，未包含完整识别/JPEG模块。

`tests/run_tests.py`包括RGB颜色与去白、面积边界、最大目标、质心、白孔、大连通域、输入只读、计时回绕、CSV容量及曝光寄存器写入/回读失败测试；还验证ROI放大裁边、奇数列YUYV、滤波邻域等价、目标移动/消失/重获、内部触边回退和会话重置。中值回归比较50组合成图的768万像素。

可选 `python tests/verify_median_filter.py` 与OpenCV比较合成二值掩膜。所有主机测试均不连接板子，不能证明实际曝光、帧率或识别效果。

**本次按要求不使用旧曝光录像进行效果验收或调参，等待新固件固定曝光后重新录制的数据。**

烧录脚本 `tools/flash_h750_dfutil.py` 默认读取 `build/native`，若使用其他构建目录必须通过 `--build-dir` 指定。烧录后可从INFO开头核对 `2.2.1-rgb-roi3ms`，再检查曝光回读通过及RGB/ROI配置。

## 电脑端历史工具

`green_light_detector/` 仍是历史HSV双掩膜/白色灯芯的OpenCV程序，其YAML不控制当前H750 RGB参数。它不再与当前机载算法等价；不要用它的检出结果作为本版本验收基准。历史使用说明见 [绿灯识别程序.md](绿灯识别程序.md)。

`tests/onboard_pipeline.c`编译当前H750生产源文件，仍可用于后续主机回放。但旧 `verify_onboard_detector.py` 比较的是历史电脑端结果，不能证明新RGB策略正确；带已有黄色叠字、圈和JPEG压缩的视频也不等同于原始相机输入。
