# DART 绿灯识别程序说明

本文说明仓库里两套识别程序的分工、入口、阈值对应关系和验证命令。适用版本：H750 固件 2.1.6-latest（2026-11-25）。

## 两套程序的分工

| | 机载识别（板端） | 电脑端识别（离线） |
| --- | --- | --- |
| 位置 | `h750/green_detector.c`、`h750/green_annotate.c` | `green_light_detector/` |
| 语言与依赖 | C11 定点运算，不依赖 HAL 和任何库 | C++17 + OpenCV 4 |
| 输入 | OV5640 直接输出的 YUV422 帧（Y0 Cb Y1 Cr，320×240） | TF 卡录像 `VIDEO.AVI` |
| 用途 | 飞行中实时检测，结果画进录像并写入 `DETECT.CSV` | 回放录像调阈值、作为机载结果的对照基准 |
| 详述 | 本文 | [绿灯识别程序.md](绿灯识别程序.md) |

两套程序使用同一套阈值和同一条判定流程，电脑端用来验证机载结果是否一致。阈值固定为“白色灯芯”配置（`green_light_detector/config/rec00038_white_core.yml`，经 REC00038/39 录像验证），当前约定不改阈值。

## 判定流程（两套程序一致）

1. 由 YUV 生成两张掩膜：绿色光晕掩膜（色相、饱和度、亮度条件），灯芯掩膜（很亮且接近白色）。
2. 两张掩膜各做一次 3×3 中值滤波，去掉孤立像素。
3. 在灯芯掩膜上找外轮廓，检查面积、长短边比、圆度。
4. 灯芯轮廓向外扩展 7 像素，要求范围内有足够的绿色像素（排除白色光源和孤立反光点）。
5. 合格候选按面积、绿色支持、圆度打分，选出一个主候选；没有合格候选时记为“未检出”，不沿用上一帧坐标。
6. 取灯芯区域质心作为中心。

机载实现里，第 3 步用 8 连通淹水填充取连通域，再用 Moore 邻域跟踪取外轮廓。

## 机载识别

### 文件

| 文件 | 内容 |
| --- | --- |
| `h750/green_detector.h` | 对外接口、全部阈值宏、结果结构体 `dart_detection` |
| `h750/green_detector.c` | 检测实现：掩膜 → 中值 → 连通域 → 轮廓 → 邻域验证 → 评分 |
| `h750/green_annotate.c` | 在帧上画黄圈、红十字、红点和中心坐标文本；未检出时写 NOT FOUND |
| `h750/main.c` 的 `process_frame()` | 每帧的完整处理顺序：检测 → 标注 → JPEG 编码 → 写入 AVI 和 `DETECT.CSV` |
| `h750/jpeg_enc.h` | 录像 JPEG 统一接口 `jpeg_encode_yuv422()` |
| `h750/jpeg_hw.c`、`h750/jpeg_mcu.c` | H750 硬件 JPEG 后端（固件实际链接的是这两个文件） |
| `h750/jpeg_enc.c` | 纯 C 软件 JPEG 参考实现，固件不链接，只用于电脑端回归 |
| `h750/camera_slots.h` | 相机帧槽状态机：处理端总是取最新的就绪帧，槽满时淘汰最旧的一帧 |
| `h750/record_profile.c` | 逐帧耗时记录，写入 `TIMING.CSV` |

`green_detector.c` 和 `green_annotate.c` 不含任何硬件寄存器操作，可以在电脑上直接编译，主机验证程序就是这样使用它们的。掩膜放 AXI SRAM，连通域工作区放 D2 SRAM，只在 `__arm__` 下生效。

### 输出

`DETECT.CSV` 每帧一行，无表头，列依次为：

| 列 | 单位 | 含义 |
| --- | --- | --- |
| 1 | 帧 | 帧序号，从 0 开始 |
| 2 | 微秒 | 该帧相对记录开始的时间 |
| 3 | 0/1 | 是否检出 |
| 4、5 | 像素 | 中心 X、Y，保留两位小数；未检出时为 0 |
| 6 | 像素 | 黄圈半径；未检出时为 0 |

坐标原点在图像左上角，X 向右，Y 向下，与电脑端 `centers.csv` 一致。同一结果写两份：画面上的黄圈和坐标文本（存入 `VIDEO.AVI`），以及 `DETECT.CSV`。

标注在检测之后进行，画上去的圆环和文字不会影响本帧的检测结果。

### 阈值对应关系

机载阈值全部是 `green_detector.h` 里的宏，与 `rec00038_white_core.yml` 逐项对应：

| 宏 | 值 | 配置项 | 值 |
| --- | ---: | --- | ---: |
| `DART_DET_HUE_MIN` / `DART_DET_HUE_MAX` | 35 / 95 | hue_min / hue_max | 35 / 95 |
| `DART_DET_SAT_MIN` | 45 | saturation_min | 45 |
| `DART_DET_GREEN_V_MIN` | 140 | green_value_min | 140 |
| `DART_DET_CORE_V_MIN` | 252 | core_value_min | 252 |
| `DART_DET_CORE_SAT_MAX` | 35 | core_saturation_max | 35 |
| `DART_DET_MEDIAN_KERNEL` | 3 | median_kernel | 3 |
| `DART_DET_SUPPORT_RADIUS` | 7 | support_radius | 7 |
| `DART_DET_AREA_MIN` | 280 | area_min | 280 |
| `DART_DET_AREA_MAX_FRACT` | 819（0.08×10000） | area_max_fraction | 0.08 |
| `DART_DET_ASPECT_MAX` | 12（2.4×5） | aspect_ratio_max | 2.4 |
| `DART_DET_CIRC_MIN` | 175（0.35×500） | circularity_min | 0.35 |
| `DART_DET_GREEN_PIX_MIN` | 20 | green_pixels_min | 20 |
| `DART_DET_GREEN_FRACTION_MIN` | 800（0.08×10000） | green_fraction_min | 0.08 |

注意电脑端的默认配置 `config/detector.yml` 不是这一套（灯芯亮度门槛 240、最小面积 80），复现机载结果时必须显式加 `--config=config/rec00038_white_core.yml`。

## 电脑端识别

源码入口 `green_light_detector/src/main.cpp`，算法 `src/detector.cpp`，参数结构 `include/detector.hpp`，阈值在 `config/*.yml`，改阈值后无需重新编译。构建、运行和输出说明见 [绿灯识别程序.md](绿灯识别程序.md)。

`CMakePresets.json` 里的预设 `msys2-local` 写死了 MSYS2 的安装位置 `D:/CppDev/msys64`，换电脑需要改这个路径。

## 编译与验证命令

以下命令都在仓库根目录执行，`gcc`、`cmake`、`ninja` 需在 PATH 中。

### 编译固件

```powershell
$env:ARM_GCC_BIN = '<arm-none-eabi-gcc 所在目录>'
cmake --preset dart
cmake --build --preset dart
```

产物在 `build/native/<芯片>/`。也可以用 `python tools/build.py`，工具链目录同样取环境变量 `ARM_GCC_BIN`。烧录工具见 `tools/flash_f103.py`（F103）和 `tools/flash_h750_dfutil.py`（H750，DFU），后者默认读 `build/native`，其他构建目录要加 `--build-dir`。

### 电脑端识别

```powershell
cd green_light_detector
cmake --preset msys2-local
cmake --build --preset msys2-local
ctest --preset msys2-local
```

### 识别相关测试

| 命令 | 验证内容 | 需要 |
| --- | --- | --- |
| `python tests/run_tests.py` | 协议编解码、AVI 头、自动触发、耗时记录容量 | gcc |
| `python tests/verify_median_filter.py` | 机载中值滤波与 OpenCV `medianBlur` 逐像素比较 | gcc、OpenCV 的 Python 库 |
| `python tests/verify_onboard_detector.py <电脑端结果目录> <输出目录>` | 把电脑端标注视频转成 YUV422，跑机载“检测→标注→JPEG”，逐帧对比 `centers.csv` | gcc、Pillow、OpenCV 的 Python 库；需先有电脑端识别结果 |
| `python tests/verify_hw_jpeg.py` | 硬件 JPEG 输入重排和适配层回调（不模拟 JPEG 外设） | gcc、numpy |
| `python tests/verify_jpeg_encoder.py --out <目录>` | 软件 JPEG 参考实现的空间方向回归 | gcc、Pillow |

`verify_onboard_detector.py` 依赖的主机程序要先编译：

```powershell
gcc -std=c11 -O2 -Ih750 tests/onboard_pipeline.c h750/green_detector.c h750/green_annotate.c h750/jpeg_enc.c -o build/tests/onboard/onboard_pipeline.exe
```

帧槽策略仿真（对比“取最旧帧”和“取最新帧”两种策略下画面有多旧）：

```powershell
gcc -std=c11 -Ih750 tests/camera_slot_sim.c -o build/tests/camera_slot_sim.exe
.\build\tests\camera_slot_sim.exe
```

以上测试都在电脑上运行，不连接板子。它们只能说明算法和编码在给定输入下的行为，实际检出率和帧耗时要以飞行记录里的 `DETECT.CSV` 和 `TIMING.CSV` 为准。

## 相关记录文件

| 文件（TF 卡 `REC#####` 目录内） | 内容 |
| --- | --- |
| `VIDEO.AVI` | 320×240 MJPEG 录像，已画圈并标注中心坐标 |
| `DETECT.CSV` | 每帧中心坐标和检出标志 |
| `TIMING.CSV` | 每帧各阶段耗时：检测、标注、编码、保存 |
| `INFO.TXT` | 本次记录的汇总信息 |
