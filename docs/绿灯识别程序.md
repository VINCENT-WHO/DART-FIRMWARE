## 如何打开与运行

在VSCode选择“文件→打开文件夹”，单独打开 `C:\RMDART\dart_firmware\green_light_detector`。这是电脑端工程，不要使用F103/H750的ARM编译配置。

按Ctrl+Shift+P，选择“任务：运行任务”，运行“识别REC00032并保存到新目录”。任务会先构建，再读取E盘视频，并把结果保存到 `C:\RMDART\数据记录\绿灯识别_REC00032_年月日_时分秒`。如果E盘未插入，先把原视频接入或修改任务里的输入路径。任务不覆盖已有结果。

使用PowerShell终端也可以按顺序执行：

```powershell
Set-Location 'C:\RMDART\dart_firmware\green_light_detector'
$env:Path="$PWD\runtime\ucrt64\bin;D:\CppDev\msys64\ucrt64\bin;D:\CppDev\msys64\usr\bin;" + $env:Path
cmake --preset msys2-local
cmake --build --preset msys2-local
ctest --preset msys2-local
$resultDirectory=Join-Path 'C:\RMDART\数据记录' ('绿灯识别_REC00032_' + (Get-Date -Format 'yyyyMMdd_HHmmss'))
.\build\green_light_detector.exe '--input=E:/REC00032/VIDEO.AVI' ("--output=" + $resultDirectory) '--config=config/detector.yml' '--debug=true'
```

修改为其他视频时，只需替换 `--input=`，输出目录必须是新目录或空目录。参数使用 `--名字=值` 格式，带空格的完整参数用引号包围。

## 算法为什么这样设计

当前视频的主灯明显过曝，白色灯芯不再具有稳定的绿色色相。只做“绿色HSV阈值”容易得到外围光晕、漏掉白色中心，或者把小反光点当成目标。因此采用以下顺序：

1. BGR转HSV，用绿色H范围、最低饱和度S和最低亮度V提取绿色光晕。
2. 另外提取V≥240的高亮区域。这里不限制灯芯色相，允许灯芯过曝发白。
3. 对绿色掩膜、高亮掩膜分别做3×3中值滤波，抑制孤立像素。这里是“中值滤波”。
4. 对高亮掩膜提取外轮廓，检查面积、长宽比、圆度。
5. 高亮区域向外扩展7像素，要求其中有足够绿色支持；白色日光灯没有绿色光晕，较小的绿色反光点通常不满足面积条件。
6. 合格候选按面积、绿色支持和圆度打分，选主发光区域。没有合格目标时明确记为未检测到。
7. 用高亮区域的几何质心作为中心，画黄色包围圆、红色中心点和十字，并显示像素坐标。

包围圆覆盖当前检测到的高亮区域，圆心取区域质心。它不代表透过过曝恢复了真实灯具边界，也不是经过标定的物理圆心。灯具斜视、部分出画或过曝不对称时，检测中心可能存在偏差。

没有采用强制霍夫圆：视频中圆灯的高亮图像已经接近方形，严格找圆反而容易漏检。圆度与长宽比使用宽松门槛，只作辅助排除。

## 阈值如何调整

编辑 `config/detector.yml` 后重新运行即可，无需重新构建。

| 参数 | 当前值 | 含义与调整方向 |
| --- | ---: | --- |
| hue_min / hue_max | 35 / 95 | OpenCV绿色色相范围；H为0～179，不是0～360 |
| saturation_min | 45 | 绿色光晕最小饱和度；太低容易收入灰白背景 |
| green_value_min | 140 | 绿色光晕最低亮度；太高可能丢掉外围绿色 |
| core_value_min | 240 | 灯芯高亮门槛；灯变暗时可适当降低 |
| median_kernel | 3 | 中值核边长，必须为1～15内奇数；1表示不滤波 |
| support_radius | 7 | 绿色支持检查向外扩展的半径，单位像素 |
| area_min | 80 | 灯芯最小轮廓面积，单位像素平方；太小可能收入反光 |
| area_max_fraction | 0.08 | 高亮区域最大面积占画面比例 |
| aspect_ratio_max | 2.4 | 长边/短边的最大值，排除细长亮条 |
| circularity_min | 0.35 | 圆度4πA/P²的最低值，理想圆接近1 |
| green_pixels_min | 20 | 扩展区域内最少绿色像素数 |
| green_fraction_min | 0.08 | 扩展区域内绿色像素最低比例 |

阈值针对当前320×240画面。更换分辨率、距离、镜头或曝光后，尤其要重新确认面积与支持半径。当前方法只选择一个主要候选；多个相似大绿灯同时出现时，不能保证一直选择同一个物理目标。

## 输出如何查看

| 输出 | 含义 |
| --- | --- |
| annotated.avi | C++直接输出的标注视频，黄色圈和红色中心点 |
| annotated.mp4 | 本次交付额外转成H.264的播放副本；C++程序本身输出AVI |
| centers.csv | 每帧一行的中心坐标、面积和形状指标，UTF-8 BOM、表头含单位 |
| summary.json | 总帧数、检测帧数、首末检测帧与处理耗时 |
| masks.avi | 调试掩膜：左侧绿色分割，右侧高亮分割 |
| frame_*.png | 每25帧及首次检测的标注预览 |

像素坐标原点为图像左上角，X向右，Y向下。帧序号从0开始。未检测帧的“检测到目标”为0，坐标为空，不使用0坐标冒充位置，也不沿用上一帧中心。

CSV的“视频相对时间_s”由帧序号÷视频标称帧率计算，是视频播放时间。它不是IMU触发时间戳，也不是曝光开始时刻；与IMU精确对齐需要使用原始DLG中的帧时间信息。

## 关于曝光与精度

当前视频已经拍好，后处理无法重新设置当时的曝光，也无法恢复饱和像素里丢失的颜色和细节。强行把画面变暗只能改变显示，不能把白色灯芯恢复成真实绿色圆形。

以后可在相机采集端降低曝光或增益，让灯芯保留轮廓，之后再确认阈值。此次没有修改相机参数或固件。当前输出是像素中心定位，尚不能直接当成角度；角度换算需要相机内参及畸变处理。
